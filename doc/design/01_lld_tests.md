## Low-level design

### Golden-row schema (exact contract — no extra fields)

```json
{
  "id": "S1-Q042",              // <source-prefix>-Q<seq>; S1..S5 = the 5 corpus sources
  "category": "cite | conflict | misroute | abstain | degrade | multi-source | basic",
  "query": "…",
  "ideal_answer": "… grounded, verifiable from corpus",
  "ideal_context": "… verbatim or near-verbatim anchor text (chunk excerpt)",
  "must_contain": ["…"],        // citation-critical verbatim strings
  "source": "S1 … S5",
  "path": "data/…"
}
```

### Files

```
data/docs/                     # corpus materialized here before authoring: s1..s5 step-series doc bundles (D14)
eval/goldens/retriever_goldens.json      # 120–160 rows, all categories
eval/goldens/query_processing_goldens.json # 60–75 rows incl. misroute negatives (#24)
eval/goldens/correctness_goldens.json    # 100–120 rows
doc/notes/01_corpus_plan.md              # sources, per-source chunk strategy, per-source counts
jupyter_notebook/NB-01_anchor_check.ipynb # scripted anchor check (your code)
```

### Authoring rules (enforced the same way the gate will enforce them)

1. **Groundedness is 100%:** every `ideal_answer` traces to a verbatim corpus anchor
   (`ideal_context`/`must_contain`). No anchor → the row does not exist.
2. **Counts are decisions** (tolerance-to-sample-size, task-01 Q&A): 120–160 retrieval
   (25–32 per source × 5), 60–75 routing, 100–120 correctness.
3. **Category minimums:** ≥5 misroute, ≥5 conflict, ≥5 abstain, ≥5 degrade per set where
   applicable — the gate can stratify on `category` later (Mod 3).
4. **No secrets:** never a query/answer containing a key/token.
5. **step4 goldens stay frozen** — step9 evals use step9 goldens only.

| ID | Case | Condition | Expected | Proven exit criterion |
|---|---|---|---|---|
| T-01-1 | Counts in range | row counts per file | 120–160 / 60–75 / 100–120 | "counts in target ranges" |
